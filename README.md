# RSI-Research
A collection of research papers, reproductions, and benchmarks on Recursive Self-Improvement (RSI).

| [MetaRSI](http://arxiv.org/abs/2609.06396)<br> (2026.9.9)<br>                                  | **RSI Target**: Model + Harness<br>**Mechanism**: 将系统拆分为 Data-RSI、Harness-RSI 和 Model-RSI，分别改进数据、执行脚手架和模型参数；通过 Transition Agent-v1 连接 operators，由 RSI2 Agent-v1 进行调度和 policy 优化，再由 MetaRSI2 Agent-v1 改进调度器。<br>**Limitation**: 依赖 verifier 才能可靠闭环；Data-RSI 主要放大已有能力，无法单独创造模型缺失的知识；实验尚未覆盖开放领域中的 general capability。                                                                | **Tasks:** 代码执行、闭式科学与数学推理。<br>**Benchmarks:** Terminal-Bench 2.1、SWE-bench Pro、GPQA-D-hard100、AIME。<br>**Baselines:** No improvement、单一 operator、固定组合、随机组合、静态路由。<br>**Metrics:** pass@1、能力增益、改进生产率和资源成本                                                                                                                             |
| [Socratic-SWE](http://arxiv.org/abs/2606.07412) <br> (2026.6.5)<br>                            | **RSI Target**: Model<br>**Mechanism:** 从 Solver 求解轨迹中提取结构化 skills，指导 Generator 生成针对能力缺口的任务；任务经可执行验证和 solver-gradient alignment 筛选后用于联合训练 Solver 与 Generator。<br>**Limitation:** 依赖固定的代码仓库、可靠的可执行测试和可信验证集；后期生成的任务逐渐重复，性能提升趋于饱和。                                                                                                                                                   | **Tasks:** 代码仓库修复、终端操作任务。<br>**Benchmarks:** SWE-bench Verified/Lite/Pro、Terminal-Bench 2.0。<br>**Baselines:** Base Agent、R-Zero、SPIRAL、Absolute-Zero、Socratic-Zero、SSR。<br>**Metrics:** 测试通过率；在 SWE-bench Verified 上迭代三轮后达到 50.40%。                                                                                                |
| [Dream-RSI](https://arxiv.org/abs/2609.14858)<br> (2026.9.14)<br>                              | **RSI Target**: Harness<br>**Mechanism:** 将探索历史转化为 replay simulator；候选 探索策略在历史树上低成本 replay，根据此结果进行改进和选择。<br>**Limitation:** 只能 replay 历史中已经探索过的分支，无法预测未出现的新结果；主要改进探索调度策略，不改变底层 discovery agent、evaluator 和 interfaces。                                                                                                                                                            | **Tasks:** 算法工程、数学优化、GPU 内核优化。<br>**Benchmarks:** Lasso Regularization Path、Sum–Difference、Circle Packing、Autocorrelation、KernelBench（VGG16、LayerNorm、ConvDiv、ConvMax）<br>**Baselines:** 递归固定探索策略、SimpleTES、sklearn、glmnet、AlphaEvolve 等<br>**Metrics:** 下游运行时间、智能体调用次数、解的质量、内核性能                                                   |
| [J-Zero](http://arxiv.org/abs/2608.26582)<br> (2026.8.27)<br>                                  | **RSI Target**: Model<br>**Mechanism**: Challenger 生成困难任务，Solver 学习回答，Judge 使用两类结构性偏好对：① Solver 回答优于 Challenger；② 分解并重组的回答优于一次性回答，并通过 Bradley–Terry 损失更新。<br>**Limitation:** 偏好顺序依赖人为设计的弱假设；Judge 从预训练奖励模型开始，并非完全从零；目前仅报告至少十轮的持续改进，不能证明可以无限提升。                                                                                                                                    | **Tasks：** 可验证与不可验证任务。<br>**Benchmarks:** 可验证：数学推理（GSM8K、MATH500、Minerva、OlympiadBench、AMC23、AIME24、AIME25）、通用推理（MMLU-Pro、SuperGPQA、BBH）、指令遵循（IFEval）；不可验证：AlpacaEval 2.0、Arena-Hard-v2.0、EQ-Bench Creative Writing v3<br>**Baslines：** 基础模型、R-Zero、G-Zero。<br>**Metrics：** 平均准确率。                                                  |
| [NeoHorse-1](http://arxiv.org/abs/2609.08183)<br> (2026.9.8)<br>                               | **RSI Target**: Model<br>**Mechanism** 结合 agentic routing、deployment harness 和 heterogeneous model pool，利用执行轨迹与结果反馈进行 curriculum SFT、on-policy distillation 和数据重分配。<br>**Limitation** 仅验证一轮 RSI 闭环，尚未证明多轮迭代能持续提升；评测范围有限。                                                                                                                                                          | **Tasks:** Agent 执行、工具调用、代码生成、指令遵循<br>**Benchmarks:** QwenClawBench、WorkBuddy Bench、PinchBench、VitaBench、BFCL V4、τ2-Bench、HumanEval、LiveCodeBench v6、IFEval、IFBench<br>**Baselines:** Qwen3.5、Spark-X、Gemma、Nanbeige、Agents-A1、Granite、Ornith、Muse-Glimmer<br>**Metrics:** Benchmark 分数、宏平均分；4B：58.94 → 64.87，9B：65.60 → 69.04      |
| [AIDE^2](https://arxiv.org/abs/2609.26457) <br> (2026.9.22)<br>                                | **RSI Target**: Harness<br>**Mechanism**：采用双层优化结构，Outer loop 修改 research agent 的搜索、记忆、上下文管理和验证机制；Inner loop 使用该 agent 完成 AI R&D tasks，并依据 private grade 选择更优版本。<br>**Limitation**：尚未证明更强的 agent 能更有效地改进自己；ignition test 仅使用 3 个 seeds，结果不足以排除随机波动。                                                                                                                                | **Tasks:** 机器学习工程、启发式算法工程、agent harness 工程、基于物理的天气预测<br>**Benchmarks:** selection benchmark；ALE-Bench；MLE-Bench；FML-Bench；WeatherBench 2；KernelBench（用于 reward hacking 测试）<br>**Baselines:** AIDE0；AIDEhuman；AIDE47<br>**Metrics:** private grade \(g(a)\)；外部 benchmark 得分；reward hacking rate；固定预算下的研究效率                           |
| [ScienceBuddy](http://arxiv.org/abs/2609.17523)<br> (2026.9.15)<br><br>                        | **RSI Target**: Model + Harness<br>**Mechanism**：内层固定模型改进 harness，外层固定 harness 并通过 rubric rewards 和 GRPO 训练模型。<br>**Limitation**：辅助模型、rubric 和评测器阶段内固定；实验基于研究者互动案例，未证明开放式科学能力增长。                                                                                                                                                                                                  | **Tasks:** 文献阅读、数据库判断、实验方案排错、基因与变异评估；另包括 JAK1 研究规划和 ARL4C 证据关联展示任务。<br>**Benchmarks:** LAB-Bench、Biomni-Eval；具体测试划分和任务数量未完整提供。<br>**Baselines:** 初始 model–harness system、初始 harness；未明确提供与其他方法的完整对比基线。<br>**Metrics:** validation accuracy、first-response accuracy、held-out test accuracy、training reward、problem coverage（Pass@4）。 |
| [SPADE](https://arxiv.org/abs/2608.19197)<br> (2026.8.19)<br>                                  | **RSI Target**: Model<br>**Mechanism** 同一个 LLM 分别扮演 Environment Designer 和 Reasoning Agent。前者生成可执行的 Python MDP 环境，后者在其中完成任务；通过 hint-based regret、difficulty anchor、corpus grounding 和 environment memory 实现自适应训练。<br>**Limitation** 依赖自动生成的环境、预训练语料提示和验证器，存在错误与 reward hacking 风险；训练成本较高，开放式持续自我改进仍未被充分证明。                                                                        | **Tasks:** 游戏推理、数学/科学推理、多轮工具使用。<br>**Benchmarks:** Reasoning-Gym、AIME 2025/2026、GPQA-Diamond、LiveCodeBench-v6、BFCL v4、τ²-bench、ACEBench-Agent。<br>**Baselines:** 基础模型、固定环境 RLVE、固定环境 GRPO，以及 AgentScaler、Agent-World、AWM、EnvScaler。<br>**Metrics:** 平均分、准确率、Pass@1、win rate。                                                        |
| [SoL-Pi](https://arxiv.org/abs/2609.20519v1) <br> (2026.9.17)<br>                              | **RSI Target**: Harness<br>**Mechanism**：通过自动研究循环优化 agent harness，筛选出四种机制：Action Fusion、Online Context Compact、ObservationPack、Evidence-Preserving Reducer。<br>**Limitation**：部分评估任务较少；Terminal-Bench 4 上完成任务数低于 Codex 和 Pi；不能据此推出 scaling law。                                                                                                                                   | **Tasks:** 软件工程、形式化数学、GPU 内核优化、multi-agent 优化。<br>**Benchmarks:** EdgeBench、Terminal-Bench 4、IMO 2026、kernel-optimization benchmark。<br>**Baselines:** Codex、Pi、Claude Code 等。<br>**Metrics:** 平均得分、token traffic、API cost、token efficiency、完成任务数、运行周期。                                                                             |
| [Self Improvement via Fast Tree-search](https://arxiv.org/abs/2609.19526) <br> (2026.9.17)<br> | **RSI Target**: Harness<br>**Mechanism:** SIFT 利用 LLM 成对评判与 Bradley–Terry 排名，结合基准准确率和访问次数选择父代；异步并行执行代码修订与评测，优先探索有潜力的 Agent 实现，并将后代加入归档继续进化。<br>**Limitation:** 不更新模型权重，搜索与评判机制固定；依赖外部评判器和基准验证，单一排名难以反映不同任务能力；Polyglot 完整评测包含搜索子集，并非完全独立的留出测试。                                                                                                                                     | **Tasks:** 编码 Agent 自进化、代码修复、终端长程任务。<br>**Benchmarks:** Polyglot-225（搜索使用 Polyglot-50）、TerminalBench 2.1（89 题）。<br>**Baselines:** SICA、DGM、HGM、无评判器消融。<br>**Metrics:** 任务准确率、CPU hours、Wall-clock time、API cost、Spearman ρ。<br>                                                                                                     |
| [HELIX](https://arxiv.org/abs/2608.13951) <br> (2026.8.14)<br><br>                             | **RSI Target**: Model + Harness<br>**Mechanism:** 提出 Model–Harness 协同进化框架（Build–Update–Rebuild），将 Harness 分解为可追溯的模块组件，通过组合与评测优化当前模型的执行表现；同时收集同一任务下不同 Harness 的验证轨迹，构建 SFT、Critic、Filter 和 Preference 训练数据，支持模型更新后重新优化 Harness。<br>**Limitation:** 仅在代码生成与修复任务上验证；搜索限于 65 个候选配置，模型更新与后续 Harness 重建主要是框架设计，尚未实证完整的多轮 Model–Harness 协同进化；组合效果不稳定，Portfolio 覆盖率依赖事后最优选择，不能直接视为实际部署性能。 | **Tasks:** 代码生成与修复、Harness 组合优化、训练数据构建。<br>**Benchmarks:** LiveCodeBench-derived（100 题）、SWE-bench（55 题子集）。<br>**Baselines:** Pi Mono、不同 Harness 组件组合（OpenCode、Nanobot、Hermes Agent）。<br>**Metrics:** 任务解决率、成功执行次数、Portfolio Coverage、验证轨迹与训练样供独立组件的严格因果消融。                                                                          |
| [Q-Evolve](https://arxiv.org/abs/2606.07367) <br> (2026.6.5)<br>                               | **RSI Target**: Model<br>**Mechanism:** Q-Evolve 在分布内强化学习框架中联合优化 Critic 与 Policy：混合专家示范和 Agent 自生成轨迹，通过加权 IQL 学习价值函数，利用 GAE 生成步级过程奖励，再通过 BPPO 更新策略；迭代收集新轨迹，实现数据、Critic 和 Policy 协同进化。<br>**Limitation:** 依赖专家示范与自生成数据混合，并非完全自主训练；分布内优化旨在缓解而非彻底消除分布漂移；实验仅验证有限轮迭代及特定交互环境。                                                                                                           | **Tasks:** 长程交互决策、具身家务任务、网页购物、科学实验。<br>**Benchmarks:** ALFWorld、WebShop、ScienceWorld（包含 Seen/Unseen 划分）。<br>**Baselines:** SFT、RFT、PPO、ETO、DMPO、QLASS、Best-of-N、Reflexion；样本效率实验还比较 RLOO、GRPO。<br>**Metrics:** 平均累计奖励、环境交互步数、Seen/Unseen 泛化表现。                                                                                      |
| [MetaSkill-Evolve](https://arxiv.org/abs/2607.05297)<br> (2026.7.6)<br>                        | **RSI Target**: Harness<br>**Mechanism:** 采用双时间尺度进化：快速迭代优化任务 Skill，慢速迭代优化控制改进流程的 Meta-Skill；通过 Analyzer、Retriever、Allocator、Proposer、Evolver 五个 Agent 分析失败、检索经验、分配搜索预算并修改 Skill，同一流水线也用于修改自身的 Meta-Skill；结合任务表现、改进效率与探索次数选择搜索分支。<br>**Limitation:** 仅修改 Skill 文件，不更新模型权重；递归范围限于五个 Meta-Skill，Agent 角色、流水线结构及更新机制固定；只在三个基准上验证有限轮进化。                                                | **Tasks:** 文档问答、多步推理、具身交互任务。<br>**Benchmarks:** OfficeQA、SealQA、ALFWorld。<br>**Baselines:** No-Skill、Static Skill、Single-Level Evolution。<br>**Metrics:** Held-out Test Accuracy、Task Success Rate。<br>                                                                                                                             |
| [DarwinX](https://arxiv.org/abs/2608.07545) <br> (2026.7.31)<br>                               | **RSI Target**: Harness<br>**Mechanism:** 冻结模型权重，通过种群搜索持续修改 Harness（Prompt、Skill、Tool、Control Flow）；采用 Preserve-and-Extend 机制，优先保留扩展任务覆盖且回退受限的变体，并通过重复评测确认改进；归档不同谱系，重组互补能力；结合失败轨迹、教师示范和自身 Rollout 生成修改建议。<br>**Limitation:** 仅优化 Harness，不更新模型权重；依赖基准验证器与多次评测，搜索成本较高；跨基准迁移仅验证单向迁移，种群选择与重组的独立贡献缺少严格消融。                                                                             | **Tasks:** 终端操作、软件工程、浏览器交互。<br>**Benchmarks:** Terminal-Bench 2.1、TerminalWorld、WebArena-Infinity、SWE-bench Verified。<br>**Baselines:** Monet (base)、Terminus-2、Claude Code、Codex、Browser Use。<br>**Metrics:** avg@5、pass@1、Held-out Success Rate、Audit-clean Success Rate。<br>                                                     |
